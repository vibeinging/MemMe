# PetMemBench VexDB-Lite 基线报告

日期：2026-09-01  
代码：`991139e892fca4e41ef493eeda6290f10d1920b7`，工作区有未提交修改  
后端：VexDB-Lite SQLite extension v0.0.17

## 结论

当前存储底座够快，不需要为了 AI 宠物换成 DuckDB，也不应先做大规模存储重构。2,000 条记忆下，查询 p50 约 1 ms，写入约 463–480 条/秒。

但当前架构还不能直接作为可靠的 AI 宠物记忆体。核心问题不是 SQLite 或向量索引速度，而是查询范围和记忆生命周期：过期记忆仍会参与回答，一次查询不能同时取全局用户记忆与当前宠物关系记忆，带宠物范围时看不到即时事件，冲突新事实也不会自动让旧事实失效。

建议保留 VexDB-Lite SQLite，下一步优先改“范围合并 + 有效期 + 冲突状态”，再接真实 embedding 和对话评测。

## 测试设置

- 固定功能场景：8 个查询 + 6 个生命周期检查。
- 性能数据：2,000 条记忆，4 个宠物范围，50 个会话，100 次查询，Recall@10。
- 每 100 条调用一次 `add_batch`。
- 使用确定性的词语/字片段 hash embedding，256 维，不调用 LLM 或网络模型。
- `enable_graph=false`、遗忘曲线关闭、rerank 关闭，避免把未使用能力算进基础存储开销。
- 三次独立 release 运行。
- 机器：Apple M4 Pro，64 GiB 内存。
- 重要限制：当前 Rust 工具链、基准二进制和 VexDB-Lite 扩展均为 x86_64，在 Apple Silicon 的 Rosetta 下运行。数字只作为当前环境基线，不能代表原生 ARM64 最终性能。

## 功能结果

### 硬门槛：10 / 11 通过

通过：

- 全局安全记忆可找回。
- 当前宠物的关系记忆可找回，未串到另一只宠物。
- 不同用户没有串数据。
- 原始事件写入后可立即找回。
- 中文短句可找回。
- 不可变记忆拒绝更新和删除。
- 同一条记忆更新后旧内容不再出现。
- 删除后不再被搜索到。
- 完全相同内容保持同一 ID。

失败：

- `expired_safety`：已在 2020 年过期的“今晚八点需要服用阿莫西林”仍然排在查询结果第一位。当前搜索路径没有过滤 `expiration_date`，这是回答安全问题，必须先修。

### 下一版目标：0 / 3 通过

- `composite_pet_context`：指定 `agent_id=momo` 后只能看到默默的关系记忆，拿不到全局“花生过敏”信息。
- `agent_scoped_fresh_event`：带 `agent_id` 后事件通道被关闭，刚买的“蓝色小鲸鱼玩具”不可见。
- `new_fact_supersedes_old_fact`：直接写入“上午十点”后，“上午九点”仍会一起返回。搜索代码里的旧事实过滤仍是 TODO。

## 性能结果

| 指标 | 三次范围 | 中位数 |
|---|---:|---:|
| 2,000 条写入总耗时 | 4,170–4,323 ms | 4,176 ms |
| 写入速度 | 463–480 条/秒 | 479 条/秒 |
| 查询 p50 | 0.982–1.039 ms | 0.996 ms |
| 查询 p95 | 1.203–1.703 ms | 1.210 ms |
| 查询 p99 | 13.033–13.311 ms | 13.306 ms |
| Recall@10 | 98%–99% | 99% |
| SQLite 文件大小 | 9,674,752–9,691,136 bytes | 9,678,848 bytes |

每次性能运行的 embedding 计数为：20 次批量写入调用、110 次单条查询调用、合计 2,110 段文本。真实模型接入后，embedding 很可能成为主要延迟，本报告没有测这部分。

### Recall 未到 100% 的原因

漏检集中在精确编号 `PETFACT-001531` 和 `PETFACT-001886`。FTS 清洗函数没有处理连字符；SQLite FTS5 会把 `PETFACT-001531` 解释成错误表达式。搜索层捕获 FTS 错误后返回空列表，因此只剩近似向量召回，精确编号偶尔会被相近编号挤出 Top 10。

这不是单纯调大向量候选数就能解决的问题。应正确生成 FTS5 查询，并让召回通道错误进入诊断信息，不能只写一条不可见的 warning。

## 架构判断

### 保留的部分

- VexDB-Lite SQLite 单文件存储。
- 事件先写入、立即可搜索的路径。
- 向量 + FTS 的混合召回。
- 不可变记忆、更新、删除和精确去重的基础能力。

### 优先调整的部分

1. 搜索前建立明确的三层范围：全局用户记忆、当前宠物关系记忆、当前会话/即时事件。一次查询合并三层，而不是用一个 `agent_id = ?` 把另外两层切掉。
2. 所有召回通道统一过滤过期和已失效记忆。过期判断必须在候选进入融合前完成。
3. 事件增加可查询的关系归属，至少支持 `agent_id` 或独立的 `relationship_id`。
4. 新事实写入时建立 `superseded_by` 或有效时间区间；搜索只返回当前有效版本，同时保留历史审计。
5. 修正 FTS5 查询构造，增加带连字符、引号和运算符的回归测试；诊断报告应能看到某个召回通道失败。

## 下一轮门槛

先让 11 / 11 硬门槛和 3 / 3 目标场景全部通过。然后在原生 ARM64 下增加 10k、50k、100k 三档数据，测冷启动、p95/p99、文件增长和并发读写。最后换成实际使用的中文/多语言 embedding，再跑对话级别的事实、时间、关系和安全评测。
