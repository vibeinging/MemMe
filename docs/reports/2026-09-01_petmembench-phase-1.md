## 结论

当前架构已经可以作为 AI 宠物记忆体的 MVP 底座继续集成，不需要换成 DuckDB。VexDB-Lite SQLite 的单文件存储、向量检索和 FTS5 足够快，真正影响可用性的范围合并、有效期、即时事件和冲突事实问题已经修通。

最终三次正式运行均达到：

- 必须场景：11 / 11。
- Phase 1 目标：3 / 3。
- Recall@10：100%。
- 2,000 条记忆查询 p50 中位数：1.762 ms。
- 查询 p95 中位数：2.086 ms。
- 写入速度中位数：442 条/秒。

这说明底层存储和检索链已经达到下一阶段门槛。它还不是生产验收：当前只用了确定性的本地测试向量，数据规模是 2,000 条，而且运行在 Apple Silicon 上的 x86_64/Rosetta 环境。

## 本轮调整

### 1. 三层查询范围

指定宠物后，一次查询现在会合并：

1. 当前用户的全局记忆，例如过敏和长期偏好。
2. 当前宠物的关系记忆，例如生日和共同经历。
3. 当前宠物范围内尚未压缩的即时事件。

其他宠物的关系记忆和事件不会进入候选集。事件使用 `metadata.agent_id` 作为保留字段，并迁移到 `events.agent_id` 和 VexDB-Lite 事件索引中，避免先全表取回再过滤。

### 2. 有效记忆统一过滤

向量、FTS、实体和时间召回现在都在融合前过滤：

- `superseded_by IS NULL`。
- `expiration_date` 未过期。
- `valid_until` 仍然有效。

过期药物和已经被新事实替代的旧事实不会再参与回答。

### 3. 冲突事实失效

直接写入带明确纠正语气的新事实时，即使图和 LLM 都关闭，也会在同一用户、同一宠物范围内做一次小范围向量候选检查。确认冲突后，旧事实写入 `superseded_by`，保留审计记录但不再召回。

本轮补充了“改成 / 改为 / 换成”等中文提示和中文数字差异判断。这个路径有意保持保守：没有明确纠正语气的隐式冲突，仍应交给图或 LLM 整理，避免误伤相似但同时成立的事实。

### 4. FTS5 真正在线

之前新建存储不会自动创建 `memories_fts` 和 `events_fts`。写入代码只在表已经存在时更新索引，而搜索又会把“表不存在”降级为向量搜索，所以表面上启用了混合检索，实际正式基准主要依赖向量通道。

现在存储打开时会检查并回填两个 FTS 索引，之后正常写入增量维护。`compact()` 不再在每次会话压缩后全表重建 FTS，避免压缩成本随历史数据量增长。

FTS 查询也会安全引用带连字符的编号，并以 OR 组合普通词语。精确编号增加了确定性匹配通道，解决 `PETFACT-001531` 一类编号偶发掉出 Top 10 的问题。

### 5. 分数方向一致

混合通道统一转换成“分数越高越好”的 RRF 分数。关闭遗忘曲线的纯向量检索仍保留“距离越小越好”，最终排序和时间加权会按正确方向处理，不再把最远结果排在前面。

## Phase 0 与 Phase 1 对比

以下均为相同机器、release 模式、2,000 条记忆、100 次查询、三次独立运行的中位数。

| 指标 | Phase 0 | Phase 1 | 变化 |
|---|---:|---:|---:|
| 必须场景 | 10 / 11 | 11 / 11 | 全部通过 |
| 目标场景 | 0 / 3 | 3 / 3 | 全部通过 |
| Recall@10 | 99% | 100% | +1 个百分点 |
| 写入总耗时 | 4,176 ms | 4,525 ms | +8.4% |
| 写入速度 | 479 条/秒 | 442 条/秒 | -7.7% |
| 查询 p50 | 0.996 ms | 1.762 ms | +76.9% |
| 查询 p95 | 1.210 ms | 2.086 ms | +72.4% |
| 查询 p99 | 13.306 ms | 14.061 ms | +5.7% |
| 数据库大小 | 9,678,848 B | 10,407,936 B | +7.5% |

延迟上升是预期变化：Phase 0 的 FTS 表没有在线，搜索实际主要走向量通道；Phase 1 会真正执行向量 + FTS + 精确编号融合，并为事件增加宠物范围索引。绝对延迟仍低于 3 ms 的本地检索目标，p99 增幅较小。这里不把功能缺失时的约 1 ms 当成可继续追求的性能基线。

## 当前架构判断

适合保留：

- SQLite 单文件作为权威数据，VexDB-Lite 作为派生向量索引。
- 原始事件先落盘并立即可搜索，后续再压缩为 Episode 和事实。
- 全局用户记忆与宠物关系记忆分层存放，查询时合并。
- 向量 + FTS + 精确标识符的混合召回。
- 旧事实保留审计，但从活动召回中排除。

暂时不需要：

- 换成 DuckDB。当前瓶颈不在分析型 SQL，也没有列式扫描需求。
- 在检索时增加 LLM 调用。当前路径保持零 LLM，适合端侧即时响应。
- 先做更复杂的记忆图重构。现有图可以作为增强通道，不应成为基本正确性的前提。
